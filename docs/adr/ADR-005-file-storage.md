# ADR-005. Файловое хранилище состояния MixCore

**Статус:** принято (решение владельца)

**Контекст.** Требование: отдельная СУБД в проекте не нужна, данные пользователей
хранятся в Navidrome. Navidrome не умеет хранить состояние приложений
(профили вкуса, правила, роли, журнал операций) и хранит агрегаты, а не события.

**Решение.** Источник правды по пользователям, аннотациям и плейлистам —
Navidrome (Subsonic API). Состояние MixCore — набор файлов в томе `mix_data`:

- `state/` — конфигурация (пользователи, профили, миксы, реестр совместных плейлистов)
- `logs/` — append-only журналы (события, операции, запуски, outbox, аудит)
- `cache/` — пересобираемый кэш, можно удалить целиком
- `vectors/` — опциональные эмбеддинги
- `lock` — advisory-lock единственного писателя

Гарантии: атомарная запись (write-temp + `os.replace` + fsync), версия схемы
`.schema_version`, компакция журналов, ежедневный бэкап.

**Рассмотренные альтернативы.** PostgreSQL (отклонено: отдельный сервис и
эксплуатация), SQLite (отклонено как «база данных», учтено в пороге пересмотра),
Redis (отклонено: pub/sub в памяти процесса, одного инстанса достаточно).

**Цена решения.** Нет транзакций, единственный писатель, горизонтальное
масштабирование не поддерживается, потеря журнала событий необратима. Риски
R-16…R-19; порог пересмотра — более 20 активных пользователей или потребность
в нескольких инстансах.
